# Plan: Blog list

Build `/[locale]/blog`: the data changes first (column renames, demo posts, the metadata row), then the pure pieces (URL state, page range), the link controls and the pending scope, then the database reads, and the page last. The checklist in this note is the ledger: a task is ticked when its delta is staged.

Related: [[2026-11-03-blog-list-design]] (the spec, read it with this plan), [[Blog Page Handoff]], [[2026-11-03-skills-page-design]], [[ADR-0002 Database and ORM]], [[ADR-0007 Testing]].

## Global constraints

- **Stages, not commits.** Every task ends with `git add` of its whole delta. The owner commits.
- **Inline, one task at a time** (`executing-plans`, without its scripts). Discuss in Russian before a task when something is unclear.
- **TDD** for logic and client components with Vitest. Database-backed output is verified with Playwright; it may write to the database during development, but no test here needs to.
- **Production database:** the exact SQL or command is shown to the owner and confirmed before every write (Tasks 1 and 2).
- **Definition of done for a task:** `npm run test:run`, `npm run test:e2e`, `npm run lint`, `npx tsc --noEmit`, `npm run build`. Start it only after the task's last edit.
- **Conventions from `CLAUDE.md`:** `FC<Props>` arrow components with named exports, props destructured on the first line, hooks typed `Use<Name>Params` / `Use<Name>`, PascalCase files with JSX, no barrels, Server Components by default, English in the repository, boundaries lint, images only through `src/shared/ui/Image.tsx`.
- **Visual values** come from [[Blog Page Handoff]], `docs/design/README.md` and `docs/design/blog/prototype.dc.html`, except where the spec overrides them. Pagination: MUI "Rounded" without borders in our tokens (the current item `bg-selected text-selected-foreground`).
- **Next.js / Base UI / Zod:** read before first use: `node_modules/next/dist/docs/01-app/02-guides/optimizing-the-static-shell.md` and `01-getting-started/08-caching.md` (Task 8), the shadcn `pagination` and `combobox` sources (Tasks 4 and 7), Zod 4 through context7 (Task 3).

## Decisions made while planning

- **Zod is installed now** (`zod@^4`, Task 3). It is part of the decided stack (forms, ADR-0006) and not installed yet; the URL schema is its first user. Reported to the owner with the plan.
- **`HomePost` becomes `PostPreview`** (Task 1): the type serves Home and the list, as `HomeExperience` became `Experience`.
- **Links carry locale-less hrefs.** `buildBlogListHref` returns `/blog?...`; next-intl's `Link` adds the locale. The pending scope reads the rendered `<a href>` (already localized) and pushes it with `next/navigation`'s router, not next-intl's, so the locale is never added twice.
- **The folding logic of the Skills panel moves into a hook** `useFoldingPanel` (Task 6), used by Skills and Blog. The two panels' layouts differ (Skills folds inside its tile, Blog's panel is its own card in the aside), so only the logic is shared. `e2e/skills.spec.ts` proves Skills did not change.
- **Validation is a pure function** (`resolveBlogListState`, Task 8) over the catalog and the match count, so the "all or nothing" rule is tested in Vitest; the database reads are tested in Playwright.
- **SQL is run by a one-off script** in the job's temp directory (not in the repository) with the project's `@neondatabase/serverless` client and `.env.local`, as for `description_short`; there is no `psql` on this machine.

## Review focus

The cases most likely to bite a visitor that no behavior in the spec names. Each has a test in the task that owns it.

1. **A tag with spaces, dots or non-ASCII letters** (`Team process`, `Next.js`, a Cyrillic tag) survives a round trip through the URL and the server's `searchParams` decoding. Task 3 (round trip) and Task 9 (a deep link with `Team process`).
2. **The last page shrinks under the visitor:** on page 2 of 11 posts at 10, switching to 20 per page lands on page 1, not on an invalid page 2. Task 3 (`nextBlogListState` resets the page) and Task 9.
3. **Double click on a pagination link** or a quick second click on another topic while the first is pending: only the first navigation happens, and Back has one new entry. Task 6 and Task 9.
4. **A modifier click** (Cmd/Ctrl, middle button) on any control opens a new tab with the full state and leaves the current list as it was. Task 6.
5. **A deep link to a topic that exists but is hidden** (`?topic=hobby`, no posts): the default list and the address `/en/blog`. Task 8 (`resolveBlogListState`) and Task 9.
