## Decisions made while planning

- **The new-tab behaviour lives in `Link`** (`src/shared/ui/Link.tsx`): a `newTabLabel` prop sets `target="_blank"`, `rel="noopener"`, appends the label as visually hidden text and turns the `showArrowIcon` arrow into ↗. One place, so the title link and "Read more" cannot drift apart. The title in the list (a plain router link in `PostCard`, Task 5 of the blog plan) moves onto `Link` without the arrow, keeping its own classes.
- **`buildPageMetadata` gains an optional `type`** (`"website"` by default, `"article"` for posts), so the other pages keep their output.
- **`RichText` gains `size?: "default" | "post"`**: the post size sets the paragraph type, the gap between blocks and round `brand` markers; `"default"` keeps every current page as it is.
- **The demo body is one document in `src/db/seed/data.ts`** (`postBody`), used by `seedContent` for a database seeded from scratch and by a new `seedPostBodies` for the live one.

## Review focus

The cases most likely to bite a reader that no behavior in the spec names. Each has a test in the task that owns it.

1. **A slug in another case or with a trailing slash** (`/en/blog/Demo-Post-4`, `/en/blog/demo-post-4/`): the first is the 404 page, the second Next's usual redirect, never a second copy of the post. Task 5.
2. **A post in a locale without its translation** (`/ru/blog/demo-post-4`): the English title, texts and tags under `lang="ru"`, and the `ru` canonical. Task 5.
3. **A long word or URL in the body or the title** at 360 px: it wraps, the page never scrolls sideways. Task 5.
4. **A post with no `content_full`**: the page ends after the lead text with the author row, no empty block. Task 4 (`RichText` is not rendered) and Task 5.
5. **The new tab from a card keeps the list's state**: after opening a post from `?topic=software&page=2`, the list tab still shows that state. Task 2 and Task 5.

## Rulings while building

- **Pre-flight:** the Interfaces blocks agree (Task 5 consumes `getPost`, `Post`, `RichText size`, `buildPageMetadata type` and `Link newTabLabel` as Tasks 2–4 produce them). No conflict.
- **Task 1:** `seedPostBodies` is one `update … where locale = 'en' and content_full is null` instead of one guarded update per row: the same rows and guard in one statement. The paragraph with a bold phrase is a literal Tiptap node in `data.ts`; no helper for one use. Read back: eleven `en` rows with one distinct body of 13 blocks; a second seed filled 0. If wrong: none.
- **Task 2:** the list title stays a plain router link with `target`, `rel` and the hidden text written in `PostCard`, not the `Link` adapter as planned: the adapter's text-link classes (brand color, underline) would fight the heading's look. The new-tab rule therefore lives in two places, `Link` and the title. If wrong: one prop on `Link` to drop its look.
- **Task 2:** the space before the hidden label sits outside the `sr-only` span: inside it, the accessible name came out as "Read more(opens in a new tab)" (a test caught it). Four existing card tests changed their expected names to include "(opens in a new tab)"; e2e locators match by substring and needed no change.
- **Task 3:** read back against the database: eleven slugs newest first; `demo-post-4` with `topicKey` `technical` and a 13-block body; `ru` falls back to the English texts with the Russian topic label; an unknown slug and `Demo-Post-4` give `null`. `contentFull` uses `localizedOptional`: it is nullable even in English.
- **Task 4:** the post size is styled from the root's `data-size="post"` with Tailwind's `in-data-[size=post]:` variant on `strong` and `li`, so the default classes stay untouched; Home, About and Projects e2e stayed green.
- **Task 5:** an unknown slug answered 404 content with status 200: for params missing from `generateStaticParams`, Next 16.3+ serves the route's App Shell at once, and the status leaves with the first bytes. The owner wants new posts without a rebuild **and** a real 404 (2026-11-04), so the page sets `ensureStatic = "navigation"` (Next's equivalent of `fallback: 'blocking'`, `node_modules/next/dist/docs/01-app/02-guides/incremental-static-regeneration-cache-components.md`): the first request for an unlisted slug waits for the complete render, so `notFound()` sets a 404, and a new post is rendered and stored on its first request. `dynamicParams = false` was the alternative, rejected because a new post would need a rebuild. Measured: `/en/blog/nope` 404, real posts 200.
- **Task 5:** on macOS the file-system route cache (`.next/server/route-cache/…`) ignores case, so `Demo-Post-4` and `demo-post-4` share a file, and survive a restart: a test request for one served the other's answer. Production on Vercel keeps a case-sensitive cache. The other-case rule is therefore tested on `loadPost` in Vitest (checked by mutation: a case-insensitive match fails two cases), and e2e checks only `/en/blog/nope`. If wrong: a local e2e run that requests another case of a real slug sees the wrong page; nothing ships.
- **Task 5:** the slug check and `getPost` live in `src/views/post/load-post.ts`, shared by the page and `generateMetadata`; `generateStaticParams` in `src/views/post/static-params.ts` with the placeholder slug `__no-post__`. Route segment config cannot be re-exported, so `ensureStatic` is written in `page.tsx`.
- **Task 5:** the Home test first clicked About's "Read more" (same tab); it now looks inside the Blog region. The 404 test allows the browser's own console error for a 404 document, as `i18n-routing.spec.ts` does.
- **Task 5:** Lighthouse locally on `/en/blog/demo-post-4`: mobile 100, 100, 100 twice (LCP 0.9 s), desktop 100, 100, 100 (LCP 0.3 s); SEO low by design (`noindex`). Screenshots match the handoff's layout; the read time and the cover are absent as decided (no demo post has a cover).
