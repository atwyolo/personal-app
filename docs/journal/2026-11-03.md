# 2026-11-03 — About page closed: chips, Back link, reveal, JSON-LD; Projects page closed

## Decided
- The Back link is a plain link home on every inner page, never a step in the history, and it keeps 30 px below it (owner's decisions). The visitor must not leave the site through it. This drops the `router.back()` enhancement from the design and the tracker that was built for it.
- The active chip is the message nearest to the top of the visible page from below. A clicked chip, or the target of a deep link, holds until the visitor scrolls by hand (owner's decisions). This replaces the handoff's 40% line and its rule for the bottom of the page.

- The hero has no label, and in the question bubble `question_title` is the larger line (owner's decisions).

## Metadata tables

### Decided
- Every configurable piece of metadata lives in four `meta_` tables named by the owner: `meta_site_settings`, `meta_site_settings_translations`, `meta_pages`, `meta_page_translations`. Titles and descriptions are translated full text, file URLs are not translated, every icon URL is optional (owner's decisions). See [[ADR-0014 Metadata in the Database]].
- The modern icon set without manifest icons: `.ico`, SVG, PNG 96, apple touch icon, OG placeholder. While no browser icon is set, pages carry `<link rel="icon" href="data:,">` (owner's decisions).
- `og:site_name` and the default title are site-wide and translated; `hidden_from_search` (the owner's name) closes the site to search engines until Stage 8, default `true` (Claude's call, accepted).
- Not stored: Search Console verification (DNS), `theme-color` (code, Stage 8), anything derived (canonical, hreflang, `og:url`).

### Done
- [[2026-11-03-meta-tables]]: the tables and their seed, the cached reads, the pure `Metadata` builders, Home, About and Projects on the tables, the root layout's default title, icons and `noindex`, `/favicon.ico` as a route handler, `profile_translations.meta_description` dropped. Nothing visible changed: the seed reproduced the titles and descriptions read from a production build. Version raised to `0.5.0`.

### Notes
- A layout's string `title` is the default of its children; Next's types allow `title.default` only with a `template`.
- Headless Chromium never requests a favicon, so a network assertion about `/favicon.ico` proves nothing; the `data:,` tag is the proof.
- The build's route table does not list `/favicon.ico`. The e2e test tells the handler's empty 404 from Next's 71 KB 404 page; it failed with the route removed.
- The foreign key of `meta_site_settings_translations` got a 68-character generated name, Postgres cut it to 63, and drizzle-kit wanted to recreate it on every push. It has an explicit name now, and the database key was renamed.
- The final review found no Critical or Important issues; the owner had its five minors fixed at once. The data guard became four `CHECK` constraints in the database (absolute `https://` URLs, no blank texts), chosen over code-side guards, so hand-written SQL is covered too.
- A `next start` from earlier in the session kept serving an old build on port 3200: `pkill -f "next start"` misses it, because the process renames itself `next-server`. Stop servers by port.
