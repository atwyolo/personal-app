## Notes
- **Mobile LCP of image pages.** Lighthouse's simulation counts against the LCP every script and font that finished before the LCP paint in the real, fast load (about 540 ms). Whether the framework's ~210 KB of JavaScript lands before or after the image is chance, so the simulated LCP is 1.5 s or 2.6 s from run to run. A spike without the locale and theme menus did not make it stable.
- A client navigation replaces the `theme-color` tags with fresh ones; `ThemeColorSync` watches `<head>` for that.
- With Cache Components a `fetch` in a route handler's `GET` stops the prerender; the favicon's `fetch` lives in a `"use cache"` helper.
- `/favicon.ico` on the preview: 200, 2,439 bytes identical to the Blob file, a real `etag`; Vercel sets `content-type: image/vnd.microsoft.icon` from the extension instead of the handler's `image/x-icon`.
- No image is loaded from Blob directly except the icons linked in `<head>`: every page image goes through `/_next/image`.
- The flaky "phone turns" test: its oracle ignored the page-end rule of `getReadingState`; under load the turns left the page at its very end. Fixed in the test; 1500 runs, no failure.
- CLS on `/ru/skills` desktop went from 0.014 to 0.043 with the wrapping chips: Geist Mono (not preloaded) swaps in after the first paint and moves a line break inside a Russian chip. Still "good" (under 0.1), score 100; left as is.
